### 2. 界面文案：把 `tlsBlocked` 显示成人话

当前 `tlsBlocked` 在 `AppModel` 里被映射成 `.unreachable` 并附原因，
**能工作但不够清楚**。建议加一个正式的 `StatusPhase`：

```swift
/// 能连上网关和 80 端口，但 443 的加密通道被切断
case tlsBlocked
```

对应文案（`CopyTable-*.swift`，三语都要）：

| key | 中文要点 |
|---|---|
| 标题 | 「加密通道被切断」 |
| 一句人话 | 能连上网关，但加密连接被中途掐断 |
| 建议 | **换节点没用**——拦截按目标地址，不按节点 |

这一条文案是本次最有价值的产出：它直接避免用户像 2026-11-11 那样
把所有节点换一遍却毫无效果。

**注意**：`StatusPhase` 新增 case 会让 `AppModel` 的 switch 不穷尽，
必须同时处理 `statusColor` / `statusSymbol` / `StatusNarrator`。

### 5. 独立修复：1.4.7 的强制重连 bug

**这是另一件事，单独一个 `[CONN]` 提交。**

`App/Sources/AppModel.swift:1306`：

```swift
if stuck > 600, cooledDown { self.retry() }
```

问题：`startOnlineWatch()` 里这个「10 分钟强制重连」安全网**不区分链路类型**。
在 JLU.WIFI 上，每次 `retry()` 都会重新登录，而 JLU.WIFI 限 3 台设备、
新登录会踢掉最早接入的那台——所以它会周期性把用户其它设备挤下线。

改法（最小改动）：

```swift
if stuck > 600, cooledDown, self.link == .wired { self.retry() }
```

加一个回归测试：无线链路上 `stuck > 600` 不得触发 `retry()`。

**为什么不在 1.5.0 一起做**：两者根因不同（一个是探测准确性，
一个是重连策略），混在一起会让回滚变难。
