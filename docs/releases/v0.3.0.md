# JLU Gate 0.3.0

> 输入框回到 **0.2.2 的实现**——就是你之前用着稳定的那一套。

## 为什么回退

0.2.7 那次我改 `updateNSView` 时，把 0.2.2 的保护条件 `!container.isEditing` 给去掉了。
SwiftUI 会把**上一次的旧值**回调给控件；旧值和内部记录对不上，
就被当成"外部改动"灌了回去——结果每格只吃一个字符，光标还跳走了。

现在直接把 v0.2.2 的 `AddressFields.swift` 恢复回来（AppKit 分段框 + 编辑中不回灌），
只留下纯展示层面的改动：段宽、标签宽度、字段含义内联。

## 连接：和 0.2.2 一致

| 文件 | 与 v0.2.2 比 |
|---|---|
| `DrcomCodec.swift` | 相同 |
| `PacketLayout.swift` | 相同 |
| `DrcomPacket.swift` / `MD5.swift` | 相同 |
| `DrcomEngine.swift` | 仅"选口"不同（有线优先/排序），不碰报文 |

## 不会崩

- 恢复回来的这版带着 0.1.3 的布局死循环修复（layout() 不改自身的 frame）；
- 本地把向导、设置各打开一次：进程活得好好的，`crash-stack.log` 也没有新增；
- `codesign --verify` 通过。
