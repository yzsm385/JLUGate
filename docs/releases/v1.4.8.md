# JLU Gate 1.4.8

> 1.4.7 的保活 B 修复**已在真机确认生效**：会话连续在线 6975 秒（≈11 个 600 秒租约周期），
> 保活 B 发送 100 包、应答 100 包、超时 0 次，10 分钟那一档的断连没有了。
>
> 这一版处理的是**更长周期**的那次断连：把「到底哪一步不通」写进日志和诊断。

## 1.4.7 实测确认的事情

诊断里 `保活B 应答 type=0x02 / 0x04` 一直成对出现，`tail` 逐包递增；
`保活A 应答 在线=` 从 0 一路涨到 **6975 秒**（1 小时 56 分），期间没有任何 B 超时。
说明网关认的就是「`0x05` = 包类型（A=01 / C=03）」，600 秒租约每次都被续上了。

## 这次要查的问题

那台机器在 ~1 小时 50 分之后开始出现 `在线巡检：探针不通`，随后系统网卡列表变成空的
（休眠/掉线），唤醒后重新登录成功、保活一切正常，但**外网探针一直不通**——
也就是「Dr.Com 是通的，但流量出不去」。老日志只写「探针不通（第 N 次）」，
看不出是 DNS 挂了、连接被丢还是被门户拦。这一版补上：

### 在线巡检

- 探针开始不通时记一条**具体原因**（哪个目标、DNS 失败还是连接失败、HTTP 状态码），
  之后每 4 次再记一条；恢复时记一条「外网恢复（之前不通 N 次，约 M 秒）」。
- 原来是 `在线巡检：探针不通（第 1 次）`，现在会写成
  `在线巡检：探针开始不通 —— connect.rom.miui.com@<ip> 连接失败；cp.cloudflare.com DNS 不通…`

### 诊断导出

新增一段，不用再靠口述：

```
== 最近一次体检 / 排查 ==
排查结论：…
建议：…
站点：共 12 个，失败 9 个（…）
体检出口 IP：…
```

## 出问题时请这样采一次

1. 断连发生时**先别点重试**，打开「体检」跑一次（它会测出口 IP / 公共站点）；
2. 再跑一次「排查」；
3. 然后导出诊断。

这样日志里会同时有：探针失败的具体原因、体检看到的出口、排查的分层结论——
能直接判断是「校园网关不放流量」「DNS 挂了」还是「代理节点死了」。
