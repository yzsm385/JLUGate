# JLU Gate 1.4.8

> 修「点『立即更新』没反应」：一键更新失败时以前是**静默**的——面板还停在
> 「发现新版本」，按钮点了像没点。现在失败原因会直接写在面板上，并记进日志。
>
> 1.4.7 的有线断联修复（保活 B 的 `0x05` 是包类型）原样包含在本版里。

## 为什么 1.4.6 点更新没反应

一键更新只能替换 **`/Applications` 里的 App**——App 没法替换正在别处运行的自己。
如果这个 App 是从 SD 卡 / 下载目录 / 别的地方打开的，1.4.6 会直接放弃，
但它把原因只写进了一个**面板看不到**的变量，所以你看到的就是「点了没反应」。

## 这一版

- 只有在 `/Applications` 里才尝试自动替换；否则**立刻打开 GitHub 下载页**，
  并在面板那一行写明原因（不再是静默失败）。
- 下载 / 解压 / 替换任一步失败，面板那行都会变成橙色错误原文；
  设置页的「版本更新」也同样显示。
- 更新相关的每一步都写进 `agent.log`（远端版本、本机版本、下载开始、失败原因），
  下次出问题导一份诊断就能定位。
- 「这个版本没有可用安装包」也会明确说出来并打开下载页。

## 从 1.4.6 升级这一次要手动装

1.4.6 里跑的就是旧的静默逻辑，所以**这一次**请手动装一次，之后就都能点按钮更新了：

1. 退出 JLU Gate（菜单栏图标 → 退出）；
2. 下载 `JLU-Gate-v1.4.8.zip`，解压；
3. 把里面的 `JLU Gate.app` 拖进「应用程序」文件夹，替换旧的；
4. 打开 JLU Gate。

> 或者用终端一把梭（App 在 /Applications 时）：
>
> ```bash
> curl -L -o /tmp/jg.zip https://github.com/yzsm385/JLUGate/releases/latest/download/JLU-Gate-v1.4.8.zip
> unzip -oq /tmp/jg.zip -d /tmp/jg
> rm -rf "/Applications/JLU Gate.app"
> ditto "/tmp/jg/JLU Gate 1.4.8/JLU Gate.app" "/Applications/JLU Gate.app"
> xattr -dr com.apple.quarantine "/Applications/JLU Gate.app"
> open "/Applications/JLU Gate.app"
> ```

## 安装 / 升级

- macOS 26+：`JLU-Gate-v1.4.8.zip` / `.dmg`
- macOS 14/15：`JLU-Gate-v1.4.8-Compat.zip`
- 1.0.1 以后可在面板上点「更新」自动升级（本版起失败会说原因）。

## 有线断联（延续 1.4.7）

网关给的是 **600 秒租约**，只有合法的保活 B 能续租；保活 B 的 `0x05` 是**包类型**
（A=01 / C=03），以前当成序号发 01/03/05/07，第三包起被网关丢弃。
细节见 `docs/analysis/wired-disconnect.md`。

验证判据：面板「在线时长」能不能超过 10 分钟不归零；
诊断「在线巡检」段会直接写 `本次会话已在线：XXXs（租约 600s：已超过，续租生效 ✅）`。
