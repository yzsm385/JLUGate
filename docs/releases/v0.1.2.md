# JLU Gate 0.1.2

> 这一版修的是一句话：**登录失败不是你密码的问题，是我们的报文版本太旧。**

## 真相

服务器拒绝登录时返回的 37 字节报文里，**第 4 个字节是错误码**，后面才是那句
容易误导人的 `ldap auth error`。我们这次收到的是：

```
05 00 00 05 15 00 … "ldap auth error"
             ↑
          0x15
```

`0x15` 在两套独立的开源实现里含义一致：**客户端版本不兼容**
（[jlu-drcom-ng](https://github.com/hZsFN/jlu-drcom-ng) 写作 `CLIENT_UPGRADE_REQUIRED`，
[sidravia](https://github.com/CaelestisAstesia/sidravia) 写作 `incompatible_version`）。

我们之前把 2025-11-02 抓到的旧版客户端常量（服务包、版本串、尾部标记）写死在代码里，
服务端认为"这个客户端太旧"，于是每次都在**密码正确**的情况下回同一个错误。

## 修法

1. 按当前社区维护实现 [jlu-drcom-ng v2.0.0](https://github.com/hZsFN/jlu-drcom-ng) 重写登录报文；
2. 服务端若回 `0x15`，**自动换回旧版报文再试一次**；
3. 界面把错误码翻成人话（密码错就是密码错，版本不兼容就直说）。

两套报文都有**逐字节黄金测试**（3 种密码长度），并且旧版布局能 100% 复现本仓库真实抓包。

## 一并修掉的

- 地址输入改回**分段格子**：点任意一段可编辑，Enter 跳到下一段，方向键切换；
- 密码不再被静默复用（0.1.1 已修，这版保留）；
- 体检、测速、状态刷新等保持 0.1.1 的行为。

## 安装

解压 → 把 `JLU Gate.app` 拖进 `/Applications`（先退出旧版）→ 右键打开（未签名）。
