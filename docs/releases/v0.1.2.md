# JLU Gate 0.1.2

> 这一版其实就修一件事，一句话说清：**你登录失败，不是密码错了，是我们报文的"版本号"太老，被服务器嫌弃了。**

## 先说清这事怎么回事

服务器拒绝你登录时，会回一个 37 字节的报文。这里头**第 4 个字节才是真正的错误码**，后面那句
看着吓人的 `ldap auth error` 反倒只是个话术。我们这次收到的报文长这样：

```
05 00 00 05 15 00 … "ldap auth error"
             ↑
          0x15
```

`0x15` 这个码，在两套互相独立的开源实现里说的都是同一件事：**客户端版本不兼容**
（[jlu-drcom-ng](https://github.com/hZsFN/jlu-drcom-ng) 把它叫 `CLIENT_UPGRADE_REQUIRED`，
[sidravia](https://github.com/CaelestisAstesia/sidravia) 写成 `incompatible_version`）。

说白了，是我之前把 2025-11-02 抓到的旧版客户端常量（服务包、版本串、尾部标记那些）写死在了代码里，
服务端一看"这客户端太老了"，于是哪怕你密码完全正确，它也每次都回同一个错。

## 怎么修的

1. 照着当前还在维护的社区实现 [jlu-drcom-ng v2.0.0](https://github.com/hZsFN/jlu-drcom-ng) 把登录报文重写了一遍；
2. 要是服务端还是回 `0x15`，就**自动退回旧版报文再试一次**，留条后路；
3. 界面也把错误码翻成了人话——密码错就是密码错，版本对不上就直说版本对不上。

这两套报文我都做了**逐字节的黄金测试**（覆盖 3 种密码长度），而且旧版那套布局能 100% 复现本仓库真实抓到的包。

## 顺手收拾的

- 地址输入换回了**分段格子**：点哪一段就改哪一段，Enter 跳下一段，方向键来回切；
- 密码不再被偷偷复用（0.1.1 已经修好，这版照旧）；
- 体检、测速、状态刷新这些，都保持 0.1.1 的样子。

## 装上它

解压 → 把 `JLU Gate.app` 拖进 `/Applications`（先把旧版退了）→ 右键打开（没签名，正常现象）。
