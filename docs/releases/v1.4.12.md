# JLU Gate 1.4.12

> 这一版只做一件事：**更新流程更快、更抗断**。
>
> 网络连接相关的代码一行没动（`make ci` 里的连接路径冻结校验可以证明），
> 1.4.11 修的问题不受影响。

## 原来的更新慢在哪

「点更新 → 卡在正在下载 → 失败 → 从头再来」这个体验，根子上是四个问题：

1. **没有断点续传**。下载中断（切网、代理抖动、休眠）之后，
   那 1.8 MB 只能从 0 重新下。慢速链路上一次失败就是几分钟白等。
2. **进度按 5% 才跳一次**。1.8 MB 的包，5% 是一百多 KB；
   在几百 KB/s 的线路上要等好几秒才动一下字，看起来像死机。
3. **卡住判定不合理**。原来是「20 秒一个字节都没多才算卡住」——
   可真正难受的情况是「还在滴字节，但慢到 0.5 KB/s」，
   这种连接不会被判定卡住，只会一直转到天荒地老。
4. **下载完直接解压安装，没有校验**。包被截断或中途被换掉，
   会把坏包装进 `/Applications`，然后再也打不开。

## 这一版怎么改的

| 改动 | 效果 |
|---|---|
| 断点续传（HTTP Range） | 失败自动带续传重试一次，不必从 0 开始 |
| 进度 1% 步进 + 实时速度 | 面板直接显示「正在下载 37%（812 KB/s）」 |
| 卡住判定改为吞吐量 | 平均低于 8 KB/s 就明确报错，不再无限转圈 |
| 下载后校验 SHA256 | 和官方 `SHA256SUMS.txt` 比对，不通过就不装 |
| 缓存策略 | 更新包强制拿最新的，不吃本地/中间缓存 |

配套地，发布流程现在会生成 `SHA256SUMS.txt` 一并上传；
App 端在更新时顺手取这份清单核对（取不到就跳过校验，不会因此卡住更新）。

## 需要说清楚的

- **DHCP 的老问题还在**：网卡是「自动获取（DHCP）」时认证仍会报 E08。
  这是 Dr.Com 协议本身的限制，不是更新器的问题，这一版没有动它。
  要连就得先把网卡配成手动 IP——和 1.4.11 一样。
- **DMG 这次有了**：CI 上跑通了 DMG 构建，所以三份产物齐全
  （`JLU-Gate-v1.4.12.dmg` / `.zip` / `-Compat.zip`）。
  一键更新用的仍然是 ZIP，DMG 适合首次安装。
  注：本机构建环境做不出 DMG，但 GitHub Actions 上可以——
  之前几版说「做不出来」是就本机而言的。
- **速度提升取决于你的网络**：断点续传和省掉重复下载是实打实的，
  但单次下载的峰值速度受线路限制，这一版不会让它变快。

## 怎么验证

更新到 1.4.12 之后，点一次更新（或者等下个版本），观察：

- 进度是不是 1% 一跳、后面跟着速度（例如 `正在下载 12%（1.1 MB/s）`）；
- 中途断网，恢复后是不是从断点继续，而不是回到 0%；
- 如果包损坏，是不是在解压前就明确报「安装包校验没通过」而不是装完打不开。
