# JLU Gate 0.3.6

> 0.3.5 的日志把话说透了：本机存着的，是一串**从来没有成功登录过**的密码，可它却一直被自动拿来用。

## 诊断里最关键的三行

```
13:25:00  使用保存的密码（来源：已保存（未验证），10 字符 / 指纹 5c1e2749）
13:25:00  发送登录包：370 字节，摘要A=1013f605b34ae80c…
13:25:00  登录被服务器拒绝：错误码=0x15
```

- 指纹 `5c1e2749` ≠ 已知可用密码的指纹 `e20f4459`，也 ≠ 11-02 成功那次用的密码；
- 服务端对**两版报文**都回 `0x15`（凭据被拒），跟版本没关系。

换句话说：程序一直拿这串"从来没成功过"的密码去登录，你界面看到的是点号，自然以为是刚输的。

## 这一版的规矩

| 保存的密码状态 | 行为 |
|---|---|
| 成功登录过（verified） | 允许自动复用 |
| 从未成功 / 上次被拒（unverified） | **不自动拿来用**，直接打开向导要你重新输入 |

重新输入的时候：
- 会弹第二个确认框，两次不一致就拦下来（防全角/空格这种小坑）；
- 显示本次密码指纹（长度 + 8 位），可以跟设置页的"已保存指纹"对一对；
- 登录成功了才写入 verified 标记；被拒就清掉。

## 你只需要做一件事

打开 0.3.6 → 点连接 → 它会直接让你**重新输一次密码**（不会再偷偷用旧的）。
要是这样还是 `0x15`，那基本就是服务器认定的账号/密码不对了，请去 `mails.jlu.edu.cn` 网页版验证；
把新日志里的"指纹"行发给我就行（不含密码）。
