# JLU Gate 0.3.11

> 拔网线再点重试这件事，这版再上一道保险，并把证据一起带回来给你。

## 这次又补了什么

0.3.10 只是拦住了"物理网口空了就别启动引擎"，可 `retry()` 用的却是**缓存里的网卡列表**——
网线一拔，缓存里可能还留着 en7 的影子，于是那道守卫被绕了过去，程序又拿一个已经不存在的接口去敲建通道的门。

0.3.11 做了两件事：

- `retry()` 会先 `refreshDiagnostics()` 再判断，拿到的就是"此刻"的网卡列表，不再吃缓存的过期账；
- 新增了一项压力测试：在没有任何物理网口的情况下，连续 `start → retry` 5 轮，
  既不崩溃、也不误报 online（已通过）。

## 关于"是不是还得等你导出报告才能修"

老实说：**崩溃栈我确实还没有**。
0.3.10 和 0.3.11 修的，是我在日志里能坐实的那条路径——接口列表空了，却还拿旧接口去建通道。
如果 0.3.11 还是闪退，那多半是界面层（AppKit/SwiftUI）的异常，跟网络这条路径无关——
这种就得看调用栈才能定位了。

好消息是：**从 0.3.10 起，导出的诊断文件里就带了「崩溃日志（最后 40 行）」**。
你只要在闪退后重新打开 App → 诊断 → 导出，发我这一个文件就行，不用再做别的。
