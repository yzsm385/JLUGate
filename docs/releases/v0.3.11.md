# JLU Gate 0.3.11

> 拔网线 + 重试：再加一道保险，并把证据一起带回来。

## 这次又补了什么

0.3.10 只是"物理网口为空就不启动引擎"，但 `retry()` 用的是**缓存里的网卡列表**——
拔线后缓存里可能还留着 en7，于是守卫被绕过，程序又拿一个已经不存在的接口去建通道。

0.3.11：

- `retry()` 先 `refreshDiagnostics()` 再判断，拿的是"当下"的网卡列表；
- 新增压力测试：没有任何物理网口时，连续 `start → retry` 5 轮，
  不崩溃、不误报 online（已通过）。

## 关于"是不是还得等你导出报告才能修"

诚实的回答：**崩溃栈我确实还没有**。
0.3.10/0.3.11 修的是我从日志里能证明的那条路径（接口列表为空还用旧接口建通道）。
如果 0.3.11 仍然闪退，那大概率是界面层（AppKit/SwiftUI）的异常，不是网络路径——
这种情况下必须看栈才能定位。

好消息是：**从 0.3.10 起，导出的诊断文件里已经包含「崩溃日志（最后 40 行）」**。
你只要在闪退后重新打开 App → 诊断 → 导出，一个文件就够，不需要额外操作。
