# JLU Gate 1.4.7

> 有线网「每十几分钟断一次」修好了：根因是保活 B 的 `0x05` 字段被当成
> 「请求/应答共用的序号」，它其实是**包类型**（A=01 / C=03）。
> 完整证据链见 `docs/analysis/wired-disconnect.md`。

## 保活 B（有线会话续租）

- `0x05` 改为包类型：每轮发 A 包（类型 01），收到应答后发 C 包（类型 03）。
  以前发的是 01/03/05/07…，**第一对恰好是合法类型所以有应答，第三包起网关全部丢弃**，
  于是保活 B 整场超时，会话在 10 分钟左右被服务端释放，表现为「隔十几分钟断一下」。
- `0x01` 恢复为每包 +1 的计数器。
- 每个会话第一轮先发一次「文件包」（版本域 `0F 27`）。网关回 272 字节确认，
  以前这包被误当成保活应答，还把它的 `0x10` 抄进后续请求。
- tail（`0x10–0x13`）只从 40 字节的 A/C 应答里取，C 包原样带回；
  A 包校验字为 0、C 包才带校验字（对齐官方抓包）。
- 保活 B 收不到回执**不再计入掉线判定**：会话存亡只看保活 A 与在线巡检。

## 在线巡检

- 连续 4 次探不到外网时，如果保活 A 仍在应答（60s 内），说明服务端会话还活着，
  只记日志不重登——诊断里「每 12 分钟重登一遍」就是这条误判。
- 保活真停了仍由原来的 120s 检查负责重连。

## 诊断

- 保活 B 逐包记录 `type / counter / tail`，应答也记；
  文件包与 272 字节确认单独一行，方便下次直接对照网关行为。

## 安装 / 升级

- macOS 26+：`JLU-Gate-v1.4.7.zip` / `.dmg`
- macOS 14/15：`JLU-Gate-v1.4.7-Compat.zip`
- 1.0.1 以后可在面板上点「更新」自动升级。

## 验证要点（真机）

跑满 8 小时，看诊断里：

1. `保活B 应答 type=0x02` / `type=0x04` 持续出现（不再只有前两包）；
2. C 包的 `tail` 等于上一行应答的 `tail`；
3. `状态：idle → discovering` 不再周期性出现。
