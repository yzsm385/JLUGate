# JLU Gate 1.4.9

> 全局代理模式下连不上 / 重连不上的问题，从技术上解决了：
> 认证通道的 socket 本来就钉在物理网卡上，**不该因为「路由表里出口是 utun」就提前放弃**。
>
> 包含 1.4.8 的排查增强（在线巡检失败原因、诊断里的体检/排查结论）。

## 问题

「开着全局代理（小火箭 / Clash 的 Global）连校园网，怎么都连不上；切成规则模式就好了，
但有时候全局模式也能连上」——原因在代码里：

```swift
// 以前：路由表里 10.100.61.3 的出口是 utun 就直接放弃
if let route = interfaces.route(to: server), route.isTunnel {
    throw DrcomError.capturedByTunnel(...)
}
```

全局模式会把两条「半默认路由」（0/1 与 128/1，甚至 10/8）塞进 TUN，`route get 10.100.61.3`
就报 utun。但我们发认证包用的 socket 是 **`IP_BOUND_IF` 钉在 en7 上**的，
报文根本不受路由表影响——所以这个判断是**误杀**：明明能通，却被提前拦下了。
这也解释了「有时候全局模式又能连上」：取决于代理当时有没有把 10/8 也接管。

## 这一版

- **不再因为「路由出口是 TUN」就放弃**：照常发 challenge（socket 仍钉在物理口）。
  - 收到回执 → 继续登录，全局代理下也能连；
  - 收不到回执 → 才报「被代理接管」，提示把 `10.0.0.0/8` 设为直连。
- 日志里会写明：`路由出口是 utun4（代理 TUN）：认证包已钉在 en7，先试一次`。
- 命令行 `jlugate-probe login` 同步：遇到 TUN 出口只提示、不再直接退出。

## 更新流程

- 下载时显示百分比（`正在下载 45%`），不再是干等；
- **20 秒一个字节都没多**就明确报「下载卡住了，检查代理/网络后重试」，
  不会再对着「正在下载」转圈到天荒地老；
- 下载失败会同时写进 `agent.log`，面板那行也直接显示原因。

> 传输速度本身取决于 GitHub 到你那条代理线路的带宽（包只有 1.8 MB）。
> 如果长期很慢，我可以在「设置」里加一个镜像地址选项，但那属于信任第三方的取舍，默认不开。

## 排查增强（来自 1.4.8）

- 在线巡检失败时记录**具体原因**（哪个目标、DNS 还是连接失败、HTTP 状态），恢复时也记一条；
- 诊断导出新增「最近一次体检 / 排查」段：排查结论、建议、失败站点、体检出口 IP。

## 仍然成立的前提

认证包能出去，靠的是「物理网卡直连」。如果代理用了**内容过滤 / 透明代理**把这条 UDP
也截走了（不是靠路由表，而是按规则抓流），那就真的收不到回执——这种情况会明确报
「被代理接管」，并提示把校园网段设为直连。
