# JLU Gate 0.3.5

> 诊断文件把问题钉死了：**程序一直在用"保存的旧密码"，却把它标成"本次输入"。**

## 证据（来自你 13:15 的诊断文件）

```
13:14:36  启动 JLU Gate v0.3.4
13:14:37  使用本次输入的密码      ← 刚启动 1 秒，根本来不及输入
13:14:38  登录被服务器拒绝：错误码=0x15
```

启动时 `AppModel.init` 就把 `CredentialStore` 里的密码读进了内存，
`connect()` 看到密码非空，就打了"使用本次输入的密码"——**它把旧密码当成了你刚输的**。

再用日志里的 salt 与摘要复算：发出去的密码不是你以为的那一串；
11-02 那次成功登录的摘要，用旧记录里的密码也对不上——说明那份记录早已过期。

服务端每次回 `0x15`。社区实现 `jlu-drcom-ng` 的对照表写明：**吉大网络里 0x15 通常就是密码不正确**
（不是"客户端版本"；两版报文都试过，都被同一个码拒绝）。

## 这一版怎么改

1. **启动不再预加载密码**：内存里只有"这次真的输入过"的密码；
2. 需要旧密码时按需读取，并标清来源（已保存已验证 / 未验证 / 本次输入）；
3. 日志打印**密码指纹**（长度 + 8 位，不含密码本身），能核对"这次到底用的哪一串"；
4. `0x15` 不再换报文版本（诊断显示两版都被拒），直接判定为凭据被拒；
5. 被拒后向导**只允许重新输入**，并出现第二个确认框；两次不一致会拦下（防全角/空格）；
6. 设置页显示"已保存密码：长度 + 指纹"，留空表示沿用，输入新密码才覆盖。

## 结果怎么判断

- 重输一次如果连上 → 之前就是旧密码在作祟，问题解决；
- 仍然 `0x15` → 服务器认定这份密码不对，请用 `mails.jlu.edu.cn` 网页版验证；
  网页能登而客户端不能，把新日志的指纹行发我，我按指纹对账。
