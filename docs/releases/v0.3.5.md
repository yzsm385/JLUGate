# JLU Gate 0.3.5

> 诊断文件把事情钉死了：**程序一直在拿"保存的旧密码"去登录，却理直气壮地标成"本次输入"。**

## 证据（你 13:15 发来的诊断文件里写得明明白白）

```
13:14:36  启动 JLU Gate v0.3.4
13:14:37  使用本次输入的密码      ← 刚启动 1 秒，根本来不及输入
13:14:38  登录被服务器拒绝：错误码=0x15
```

启动时 `AppModel.init` 就把 `CredentialStore` 里的密码读进了内存，
`connect()` 一看密码非空，就打上"使用本次输入的密码"——**它把旧密码当成了你刚输的那一串**。

再用日志里的 salt 和摘要复算一遍：发出去的密码并不是你以为的那一串；
11-02 那次能成功登录的摘要，拿旧记录里的密码也凑不上——说明那份记录早就过期了。

服务端每次都回 `0x15`。社区实现 `jlu-drcom-ng` 的对照表写得很清楚：**吉大网络里 0x15 通常就是密码不对**
（不是"客户端版本"那回事；两版报文都试过，都被同一个码挡了回来）。

## 这一版怎么改

1. **启动时不再预加载密码**：内存里只留"这次真真切切输入过"的密码；
2. 需要旧密码时按需读取，而且会标清来路（已保存已验证 / 未验证 / 本次输入）；
3. 日志里打印**密码指纹**（长度 + 8 位，不含密码本身），方便你核对"这次到底用的是哪一串"；
4. `0x15` 不再换报文版本了（诊断显示两版都被拒），直接判定成凭据被拒；
5. 被拒之后向导**只允许重新输入**，并会弹第二个确认框；两次不一致就拦下来（防全角/空格这种小坑）；
6. 设置页显示"已保存密码：长度 + 指纹"，留空表示沿用旧的，输入新密码才覆盖。

## 结果怎么看

- 重输一次如果能连上 → 之前就是旧密码在捣鬼，问题解决了；
- 还是 `0x15` → 服务器认定这份密码不对，请去 `mails.jlu.edu.cn` 网页版验证一下；
  要是网页能登、客户端不行，把新日志里的指纹行发我，我按指纹跟你对账。
