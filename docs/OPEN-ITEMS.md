## B. 在那台 Mac 上要跑的测试

> 前提：那台机器有线在线、代理 TUN 常开、官方客户端在用。**施工机（本机）没有任何 Dr.Com 环境，一条也跑不了。**
> 按"打扰程度"排序，P0 随时可做、几秒钟；越往下越麻烦。

### P0 · 零打扰（随时，各 3–5 秒）

```bash
# 1. 官方客户端是否占着 61440（判断我们将来会不会抢端口）
sudo lsof -nP -iUDP:61440

# 2. 有线网卡的真实 MAC（我们登录帧里要用的就是它）
ifconfig en7 | grep ether

# 3. 系统网络是不是"手动"（若是 DHCP，我们的认证必失败）
ipconfig getsummary en7 | grep -i configmethod

# 4. DNS 配置（是不是学校分配的那两个）
scutil --dns | grep nameserver | head -5

# 5. 网关 ARP（确认 10/8 那条路由的下一跳真的在链路上）
arp -an | grep 10.100.61.3
```

产出：五行输出。用途：确认 MAC、确认 Manual、确认端口占用、确认网关。

### P1 · 短打断（约 30 秒断网）

```bash
# 6. U7d：那条 10/8 路由到底是谁加的
#    退出官方客户端（菜单栏 → 退出），等 30 秒，然后：
netstat -rn | grep '^10 '
#    若这条消失 → 官方 helper 装的；若还在 → 系统/手工配置
```

> 这一步会断网半分钟，但能一次性回答"我们卸掉官方客户端后会不会立刻不能上网"。

### P2 · 抓一次完整登录（约 1 分钟断网，**最重要**）

这是 U1/U2/U4/A2 的全部答案来源。

```bash
# 终端 A：开抓（en7 是那块 USB 网卡，若换过口先用 route -n get 10.100.61.3 确认）
sudo tcpdump -i en7 -n -s 0 -X "udp port 61440" -w ~/Desktop/login.pcap

# 终端 B：观察（可选，人肉看时序）
sudo tcpdump -i en7 -n "udp port 61440"

# 然后在官方客户端上：
#   ① 点"注销" → 等 5 秒            （抓 Logout）
#   ② 用【错误密码】登录一次 → 失败   （抓错误码）
#   ③ 用正确密码登录 → 成功           （抓 challenge/login/keepalive 全套）
#   ④ 保持 60 秒不动                  （抓服务器是否主动发保活探测）
#   ⑤ Ctrl-C 停止抓包
```

产出：`login.pcap` + 终端 B 的文本。**这个文件能一次性解掉 U1、U2、U4、A2 和半个 U8。**

> 注意：里面含账号和密码的 MD5，属于敏感数据。回传前可以只给 pcap，我在本地解析；不要贴到公开地方。

### P3 · `JLU.PC` 无线（约 2 分钟断网）

```bash
# 连上 JLU.PC（此时官方客户端要保持在"无线/适配器"模式）
sudo tcpdump -i en0 -n -s 0 -X "udp port 61440" -w ~/Desktop/jlupc.pcap
# 同时另开一个窗口：
netstat -rn -f inet | grep -E '^(10|default)'
```

一次解决三个问题：

- **U9b**：无线是不是同一套 61440 协议、帧格式有没有差异；
- **U9c**：无线下有没有 `10/8` 直连路由（没有的话，我们的认证会被 TUN 吞掉）；
- **U5/U12**：有没有 EAPOL（`sudo tcpdump -i en0 -n "ether proto 0x888e"`），以及 Wi-Fi 的 MAC 是否也要登记。

### P4 · `JLU.WIFI` 网页认证（约 3 分钟，不需要 root）

```bash
# 连上 JLU.WIFI，打开 Chrome → F12 → Network → 勾选 Preserve log
# 走一遍完整的网页登录（输学号密码 → 成功）
# 右键任意请求 → Save all as HAR with content → 保存
```

产出：一个 `.har` 文件。解决 **U10**（入口 URL、表单字段、有无 JS 加密/验证码）与半个 **U11**（会话多久过期）。

### P5 · 可选，收益递减（按需）

| 测试 | 命令 | 价值 |
|---|---|---|
| 保活停多久被踢 | 手动退出官方客户端，计时到网页被拦 | 决定"心跳丢失 3 次即重连"是否太激进 |
| 双设备顶号 | 两台机器同账号先后登录 | U8 错误码 |
| 断网 5 分钟再恢复 | 拔网线 5 分钟插回 | 验证退避与恢复 |

## C. 每个未决项卡住哪个里程碑

| 未决项 | 卡住 | 不解决能不能开工 |
|---|---|---|
| U1 / U2（登录与保活字节） | M1 编码器 | ✅ 能：先用 `PacketLayout` 占位，结构写对，字节后填 |
| U4 / U8（错误码） | 错误文案 | ✅ 能：先归为"服务器拒绝"，后补细分 |
| U3（端口是否强制 61440） | 端口策略 | ✅ 能：默认绑 61440，失败再降级 |
| U5（`JLU.PC` 有没有 802.1X） | 无线范围 | ⚠️ 半能：可能多出 3–5 天工作量 |
| U9b / U9c（无线帧与路由） | 无线可用性 | ⚠️ 半能：可能"有线能用、无线不能用" |
| U10 / U11（Portal 流程） | M4.5 自动化程度 | ✅ 能：WKWebView 兜底，不依赖细节 |
| U7b（无路由时绑定是否可用） | helper 的必要性 | ✅ 能：三层降级已经覆盖两种结果 |
| U7d（路由是谁加的） | 产品文案 | ✅ 能：只影响"要不要自带 helper"的说服力 |
| A1（开发者账号） | M5 发布 | ❌ 不能：没账号发不出去 |

## D. 我建议的最小行动集

如果只想花 5 分钟：**跑 P0 五条命令 + P1 的 U7d 判定**。这六条能确认 MAC、确认系统是手动配置、确认端口占用、确认路由归属——四个最容易翻车的前提。

如果愿意花 6 分钟（含 1 分钟断网）：**加 P2 的登录抓包**。这一个文件能把编码器从"占位"变成"可实现"，直接解锁 M1。

其余（P3/P4/P5）可以等 M2 之后再安排，不阻塞开工。
